# 用自己的数据：先填路径，再核对语义

## 路径与参数清单

下面是交接用清单，不是脚本自动读取的配置文件。配套脚本通过命令行参数接收值，不读取 JSON/YAML 配置，也不自动搜索作者的示例目录。

| 项目 | 提供什么 | 传给哪里 |
|---|---|---|
| 运行阶段 | 只读检查／从 PDB 聚类／已有结果选取／绘图 | 告诉 Codex 本次范围 |
| Skill 位置 | 本交付件正式 Skill 文件夹的绝对路径 | 定位 scripts；不修改源码 |
| Python | 已检查依赖的解释器绝对路径 | 所有阶段使用同一个环境 |
| PDB 目录 | 本批待分析 PDB 的目录 | `--pdb-dir` |
| 评分表 | 名称与 Average_dG 的 CSV 绝对路径 | `--metrics` |
| 链 ID | 本批需要比较的单字符字母或数字链 ID | `--chain`，脚本默认 B，需核对 |
| TMalign | 系统兼容程序的绝对路径 | `--tmalign`；仅重算聚类需要 |
| 聚类阈值 | 0 到 1 的有限数值，默认 0.5 | `--threshold` |
| 进程数 | 正整数，默认 1，不超过实际可用核数 | `--workers` |
| 新运行目录 | 自己数据目录之外或自己指定的独立结果位置 | 每次使用全新目录 |
| 主要簇最小人数 | 正整数，默认 5 | 建议配额、主要簇图和叠加图的 `--min-n` 一致 |
| 代表建议总数 | 正整数，默认建议 100 | 配额建议脚本的 `--total` |
| 现有结果（可选） | 同一次运行的 clustering.txt、矩阵和 centers.csv | 已有结果时跳过重算，不拼接不同批次 |

BindCraft 的某个 runs/Accepted 目录可以是输入来源，也可以自己建立只含本批 PDB 的目录。目录名不是算法条件，不要求使用 BindCraft 或作者的靶点。CSV 放独立位置，避免误以为它控制 PDB 入选范围。

## 1. PDB 和名称必须对应

当前聚类脚本使用目录第一层 `*.pdb` 文件，不递归。为兼容不同平台，建议统一小写扩展名；PDB 内容必须是真正的 PDB 文本而非把 mmCIF 改后缀。名称建议不含空格，避免后续文本解析歧义。每个文件应代表一个明确结构，避免多 MODEL 或未处理的替代原子记录混入；这些记录不会被自动去重或择优。

这是一张**虚构格式说明表**，不是研究数据：

```csv
Design,Average_dG
sample01,-80.0
sample02,-70.0
```

对应的文件可以命名为 `sample01_model1.pdb`、`sample02_model1.pdb`。PDB 匹配先去末尾 `_chain字母数字`，再去末尾 `_model数字`，随后只保留 ASCII 字母数字并转小写。CSV 名称只取去扩展名的 stem、保留 ASCII 字母数字并转小写，不执行相同的 model/chain 去后缀。因此 CSV 的 Design 用 `sample01`，而不是照抄 `sample01_model1`。

CSV 名称列依次优先选 `design_name`、`Design`、`Name`、`description`、`Description` 中第一个存在的列。建议只保留一个明确名称列。不同原始名称在去符号及大小写归一化后可能撞名，例如 `a-b` 和 `ab`；当前代码对重复 CSV 键使用最后一行，所以必须在开算前核对，不把覆盖当作合理映射。多个 PDB model 指向同一个 Design 时会共享同一分数；先确认是否符合本批数据语义。

PDB 必须全部有评分；CSV 多余行不会筛掉目录中的 PDB。若只想分析某个子集，先明确准备对应输入集合，而不是只减少 CSV 行。每个 PDB 均须有目标链的 ATOM CA，所有 PDB 应比较同一链角色；链 ID 不一致时先报告，不默认修改原文件。

## 2. 评分含义不是任意替换

聚类固定读取 `Average_dG`，要求匹配到的值是有限数值，按**越小越优先**决定中心。这里的已验证示例中，它就是 Rosetta dG_separated（REU）。另一个来源也应确认定义与方向；不要把 pLDDT、ipTM 或任意“越大越好”的分数简单改列名来运行。字段选择或中心规则需要变化时属于另行明确的代码改动，不是路径配置。

前两张图保留 `Rosetta dG_separated (REU)` 轴标题，第三张使用 `Binding energy`。换用不同定义或单位时，应先确认标签适用性；不要因有数值就声称单位已验证。

## 3. 三个默认设置分别调整

- **阈值 0.5**：控制成员对当前中心的平均 TM-score 条件，不是同簇成员两两相似的保证。可用 `--threshold` 改为其他任务指定值；改变后需从聚类重新生成配套结果。
- **主要簇至少 5 个**：只改变后处理展示／建议配额纳入范围，不重新聚类。更改时同步设置建议配额、主要簇图和叠加图的 `--min-n`；全部簇图保持 1。
- **建议选取 100 个**：不是每个项目的强制数。建议配额按簇大小平方根比例、有上下限分配；可用 `--total` 调整，或审阅修改本次 plan.csv 后再选取。脚本不会把不足 100 静默减小，也不会自动纳入小簇。

例如只有 3 个簇、每簇 3 人时，默认 min-n=5 下没有候选；即使改为 1，总容量也只有 9。用户明确选择“包括小簇、选取 6 个”后，才能用 `--min-n 1 --total 6`，两张主要簇相关图也使用 1。total 还不能小于纳入簇数，因为每个纳入簇至少保留 1 个中心。

若更换数据，必须重新建议／确认配额，并重新生成名单，不复用作者的 100 个具体名额。`recommended_n_for_MD` 是现有配额列名，沿用接口不等于执行分子动力学；输出 selected.csv 是名单，不自动复制 PDB 或运行模拟。

## 4. 只处理已有结果

跳过 PDB 和 TMalign 步骤，从本次 `centers.csv` 生成配额，用同次 `clustering.txt` 和 `global_tm_matrix.csv` 选取，再把新名单显式交给叠加图。只画前两张图只需该次 clustering.txt；只画叠加图另需该次 selected.csv。不自动把任意格式的其他软件输出当成兼容输入。

推荐目录及完整命令见 [commands.md](commands.md)。重新聚类时输出目录须不存在，后处理父目录需先创建，目标文件也须为全新路径。任何失败后的目录都是部分结果，不自动续算或混用旧文件。
